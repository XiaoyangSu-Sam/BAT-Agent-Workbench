# Add JupyterHub execution to an existing installation

The v0.7.6 pull request is an incremental update against the public v0.7.5 source. Each chat can start its own Python kernel on the user's existing Jupyter server to run code from a local project. The [JupyterHub guide](../jupyterhub.md) covers setup and a small analysis you can repeat.

## Apply the feature

Use the pull request's **Files changed** view or download its unified diff by appending `.diff` to the pull request URL. Open the destination checkout in your editor. Give Copilot the downloaded diff and the prompt below. You can also supply a separate checkout of the feature branch so Copilot can inspect new files.

The individual files are grouped here by their purpose.

- **Remote transport and tools.** The Hub client handles sign-in, user-server discovery, kernel channels and cleanup. The session routes select the active target. The tools send approved source and handle notebook outputs.
- **Workbench and runtime integration.** Existing handlers register the new routes and tool schemas, identify the execution target in approvals, persist its kind on the session and restore a disconnected remote session after a restart.
- **Verification and packaging.** Python tests exercise transport and dispatch. The browser smoke script covers the controls. Version metadata, documentation and the public source manifest describe this delta.

## Acceptance on the destination

1. Re-run a known context-compaction or long-chat case using the destination's existing checks. Start a local conversation and confirm that local execution and the file editor still work.
2. Sign into a running personal server using the connection dialog and select a Python kernel. Enter a short cell, decline its first execution, and verify that it produced no file. Submit it again and approve it.
3. Follow the two-cell example in the [user guide](../jupyterhub.md). Check the printed value in BAT and the generated file in JupyterLab. Try one local notebook cell and confirm its saved output in the local notebook.
4. Disconnect and check the kernel list in JupyterLab. After a BAT restart, a chat that was still targeting JupyterHub should request reconnection before executing.
