# Add portable Skill import to BAT Agent

This update applies to v0.7.6. BAT can install complete Skill folders from a fixed Git repository, a ZIP file or an extracted directory. Both the Skills panel and chat use the same importer.

Extract the incremental update ZIP outside the destination checkout. Give Copilot the patch, this prompt and the changed-file list below.

```text
Add portable Skill import to this BAT Agent v0.7.6 checkout using the supplied v0.7.7 patch and UPDATE.md. Read the destination AGENTS.md and inspect git status first. Record a baseline check for existing context handling and JupyterHub.

Run git apply --check with the supplied patch path. Apply clean changes and merge overlapping hunks by purpose. In runtime/context.py, integrate only the bounded Skill catalog in the system prompt. Preserve custom context logic, JupyterHub integration, existing Skills, workspaces, local settings, Git settings and the current Python environment. Keep the local copy of a same-named Skill whenever its contents differ. Do not replace directories wholesale, run npm install or uv sync, or create a virtual environment.

Use the existing interpreter to run scripts/check_environment.py, the Skill import tests and the existing regression suite. Verify ZIP import, folder import, and repository import with disposable data. Verify immediate registration, a byte-identical retry, and a mixed batch containing one edited installed Skill and one new Skill. Confirm the edited folder stays intact and the new one is installed.

Keep private repository addresses, credentials and imported Skills out of Git and chat. The user will enter their clone URL in the local Skills panel. Report changed paths, conflicts and test results, including what still needs a live repository check. For a customized release, regenerate SOURCE-MANIFEST.json from reviewed, staged public files using the destination packaging procedure.
```

## Acceptance on the destination

1. Open **Skills → Import Skills → ZIP file** and preview a disposable archive containing two Skills. Install both, then repeat. Both should appear in the registered list and the repeat should report identical content.
2. Edit one installed test file. Import the edited Skill alongside a new Skill. Check that the first reports a conflict, its local edit survives, and the new Skill is registered.
3. Under **Configured repository**, enter the clone URL and optional Skills subfolder, then save and preview. Select a test Skill. Confirm its folder name, a nested resource, and its availability in chat. The account running BAT needs read access.
4. In a conversation, ask BAT to install a Skill by name. Check the approval target and final per-Skill results. Re-run the destination's context and JupyterHub checks.
